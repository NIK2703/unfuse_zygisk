# unfuse_zygisk

Zygisk-модуль: доступ приложений к `/data/media` без FUSE и scoped storage. `github.com/NIK2703/unfuse_zygisk`.
Работать только в `E:\projects\unfuse_zygisk` (ветка `fuse-only`); `H:\projects\unfuse_zygisk` заброшен.
Разборы — `docs/fuse-root-patch-design.md`; устройство — скилл `zygisk-module-device-regression-sweep`.
Подробности заходов — в дневных логах `memory/2026-10-*.md` (там же полный разбор падения MGC).

## Конвенции
- Комментарии/коммиты по-русски, **почему** со ссылками на AOSP. Проза в `tools/` на практике **смешанная** (русская в `vold-*`/скриптах устройства, английская в отдельных пробах) — **спрошено у Nikita**, правило и практика расходятся.
- `./build.sh`, NDK `29.0.14206865`, сборка **детерминированная** (неизменный md5 при изменённом исходнике = правка не доехала). ABI: `arm64-v8a`, `armeabi-v7a`.
- Бинарники с устройства → `device/` (`.gitignore`). Файлы не удалять без согласия.
- На живое устройство — **только атомарно** (временный файл + `mv -f`; `cp -f` поверх `zygisk/*.so` усекает inode → SIGBUS в zygote). Новая сборка **не активна до перезагрузки** (zn-daemon держит старый fd).
- **Модуль не выдаёт ничего** (ни logcat, ни журнала, ни stdout) — отчёт только кодом возврата; логгирование **удалять целиком**, не заменять на `printf` (указание Nikita). Дев-харнессы вывод сохраняют — он и есть результат.

## Ядро дизайна
- FUSE-маунт **обязан** жить: fd — контракт с MediaProvider; `active` ставит только `pf_init` (ядро, на живом маунте). Убрать FUSE целиком нельзя (том `unmountable`).
- Маунт `/mnt/user/<u>/emulated` приходит в namespace приложения сам (слейв init); `MS_REC|MS_PRIVATE` в namespace приложения рвёт связь. Путь распознаётся **по форме** (конец на `/emulated` + `MS_LAZYTIME`), не по значению.
- `find_fuse_site()` (`tools/vold-fusefs.c`) ищет площадку **не по смежности**: `adrp`+`add` компилятор ставит то подряд (14–17), то вразбивку (11/12/12L/13). Требование смежности молча стоило патча FUSE на 4 релизах (rc=2). Одна функция на все версии, ветвлений по релизам нет. `MS_LAZYTIME`-площадка ровно одна во всех 8 образах. Регрессия ловится `anchor_selftest()`, коммит `3a83678`.
- `scan_back()`: связывание = «ближайшее к вызову» → берётся **первое найденное** (`out->… < 0`); иначе `x0_from == src_reg` не сходится → rc 8, патч не встаёт молча. `w3` — исключение, обязан **накапливать** половины. Окно 32 слова назад, `bl` окно не рвёт. Тест — случай 3 в `anchor_selftest()`.
- Переполнение списка площадок → `too_many` → отказ `18` **до** фильтра по LAZYTIME (иначе фильтр читает за массивом → чужой `src_va` → молчаливый провал `mount(2)`). A/B при `MAXSITE=1`: старый rc=0 (ложный успех) на 8 образах, новый rc=18.
- **Отказ называет причину, а не «2»**: `vold-fusefs` `5..10` — якорь, `11..17` — дом не получен (`vold_exec_page`/ptrace), `18` — площадок больше списка, `19` — аргументы; печатает `word()` в `vold-targets.sh`. `ep_exit_code()` — **без `default:`**; `EP_OK` там = `17` (путь отказа забыл причину — баг).
- **Места в образе нет ни на одном релизе** (`--room` → 1 везде): `find_handler_room()` не срабатывает, `vold_exec_page()` — **единственный** путь.
- Применимость по образам: libc — `verify-hook-targets.py` (8 образов arm64: ok=22/0/0), vold — `tools/vold-targets.sh` (оба патчера, `--dry-run --file`).
- **armeabi-v7a не реализован, хотя собирается и упаковывается**: `patch_entry()` под `#else` → `false` (хук-пустышка), `vold-common.h` разбирает только ELF64 → vold-патчеры отказывают (rc=2, до записи). `verify-hook-targets.py` даёт rc=1 на не-AArch64. Решение по ABI — за Nikita.
- `vold.rc` → `reboot_on_failure`: **SIGSEGV в vold = bootloop**. `libfuse` в vold **нет** (сырой syscall `mount("/dev/fuse",…)`, `Utils.cpp:1676`), входит только через `libfuse_jni`.

## Имя vold и разбор vold
- vold запускается **не голым** (`--blkid_context=u:r:blkid:s0 …`, Android 16). `/proc/<pid>/comm` = `binder:<pid>_<n>` → **по comm не опознать**. Опознание: `/proc/<pid>/exe` (под root всегда) → имя целиком; резерв `/proc/<pid>/cmdline` (мир-читаемый) → NUL→пробел, **обрезать по первому пробелу**. Префикс в 4 байта принимает `vold_prepare_subdirs`.
- Вынесено в `tools/proc-name.h` (`base_name`, `cmdline_is_vold`) и `tools/stubs.h` (`Stubs`). Оба выноса **тождественны** (md5 8 артефактов до/после совпал). Хостовые тесты (`test-stubs-oom.sh`, `test-proc-name.sh`) **не включают `vold-common.h`** — в MSYS2 нет `<elf.h>`, в MinGW нет `O_CLOEXEC`/`pread`.
- `count_call_sites()`: отказ чтения = `-1`, **не** частичный счёт («вызовов ровно 1» — ворота). В `resolve_sym()` (`vold-fusefs`) наоборот осознанно fail-safe: трамплины живут только в `.plt`.

## Сторонние патчеры кода в приложениях (2026-10-08, исправлено)
- Порт GCam (`com.android.MGC_9_7_047`) распаковывает `*.lck` в `cache/` и `dlopen`-ит; внутри — **свой патчер кода**, тоже вешает входы libc. Root не нужен: правится **своё** адресное пространство (как и модуль под uid приложения).
- Он **закрывает вход своим 16-байтным переходником** (`ldr x17,#8; br x17; .quad <impl в .lck>`, литерал по `entry+8`, оригинал возобновляется с `entry+16`). Заметив чужой переходник, строит трамплин, который **читает указатель по `entry+12`**, — а это середина его же переходника, и он затирает его своим старшим словом. Выходит невыровненный адрес → `br x17` → `SIGBUS/BUS_ADRALN`. Патч порта — ~432 мс от запуска, падение — через ~35 мс.
- **Формой патча это не лечится**: подстановка в живой процесс любой формы (порта, модуля, `bti jc`→`nop`, литерал по `+16`) роняет всё — порт считает чужим хуком **любой** переходник на входе.
- **Лечение — сторож входа** (`hook_libc.cpp`): поток возвращает свой 20-байтный переходник, как только видит чужой. Тогда по `entry+12` снова адрес обработчика, и чужой трамплин попадает в него. Опрос частый первые 3 с, дальше редкий. Проверено на устройстве: MGC без перезапусков (до правки — перезапуск каждые 200–400 мс), доступ к `/data/media` прямой. Коммит `fedb581`.
- **Цена сторожа ≈ 0** (замер A/B, 155 потоков, окно 10 с): сторож — **единственный** поток процесса в `__arm64_sys_nanosleep` (при выключенных хуках таких нет вовсе, т. е. опознаётся по `wchan`), израсходовал **2 тика = 0.2 %** одного ядра. Расход процесса целиком: хуки вкл — 1353 тика, выкл — 1352. Значит ~135 % ЦП в покое — **собственный** (MGC `frame-quality-s`, `CallbackHndlr`, `Jit thread pool`), к сторожу и порту отношения не имеет.
- Грабли замера: `startstack` (поле 28 `/proc/<tid>/stat`) **не** по-поточное — у всех 155 потоков одно значение (`mm->start_stack`), опознать поток по размеру стека (64 КиБ) **нельзя**; опознавать по `wchan`+A/B.

## Два варианта `vold-fusefs` (оба обработчика обязательны)
- **STACK** = `fuse-only` @ `5c743f3`: FUSE + bind `/data/media` **сверху** на одном `fuse_path`; `umount2` снимает до 4 слоёв.
- **RELOCATE** = ветка `relocate` @ `ecb48eb`: FUSE → `SCRATCH = fuse_path + ".fuse"`, `fuse_path` — **один** слой bind. Путь читается **побайтово** (8-байтовое чтение чужого `std::string` → SIGSEGV → bootloop).

## Грабли устройства
- `adb shell "su 0 sh /data/local/tmp/x.sh"` (adb рвёт по `;`); демон adb умирает между вызовами — переподключаться. `adb pull` ждёт **Windows**-путь (`E:/…`).
- `nsenter` **работает** под `su -c` (KernelSU), но обязателен `--` перед командой. Без nsenter путь читается резолвингом `/proc/<pid>/root/…`.
- toybox `stat` не разыменовывает симлинк, `chown` — разыменовывает. f2fs: `stat -f -c %t` → `0xf2f52010`; fuse → `0x65735546`.
- 64-битная арифметика в шелле: `$((16#hex/4096))` (mksh). `head` в пайпе **молча** обрезает вывод — считать `grep -c`.
- Процесс, живущий доли секунды, ловится своим статическим arm64-трассировщиком (NDK clang, `PTRACE_ATTACH` + `GETREGSET`/`SIGINFO`) или циклом `kill -STOP` + `cat /proc/<pid>/syscall`.
- IP устройства меняется после перезагрузки (сообщает пользователь).
