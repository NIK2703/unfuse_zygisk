## Добавлено в диагностику

- **`diag.sh --path <путь> [--uid <uid>]`** — разбор произвольного пути из чужого лога: печатает
  **все** компоненты (режим, владелец, оба ACL). Нужен потому, что падение из логов — на уровень
  ниже `<pkg>` (`Android/data/<pkg>/cache/am.log`), а автоснимок знает только `<pkg>`.
- **Проба в двух namespace.** `probe_at` гоняет пробу в корневом namespace и — если есть живой
  процесс с этим uid — внутри его mount-namespace через `nsenter -t <pid> -m -- …`. Совпало —
  причина в дереве; разошлось — бинд не дошёл. Грабли: **`--` у nsenter обязателен**, иначе toybox
  разбирает `--probe` как свой ключ («Unknown option»).
- **Проба существующего файла.** Если путь есть и это обычный файл — `open(O_WRONLY|O_APPEND)` без
  записи (случай `cache/am.log`: файл существовал, прежняя проба отказывалась и молчала). Каталог/
  ссылка/fifo по-прежнему не трогаются.
- `--probe <pkg>` дополнительно проходит `<pkg>/cache`, `<pkg>/files`, `<pkg>/no_backup`.
- В снимок добавлены `getenforce` и версия модуля.
- **uid пакета:** `cmd package list packages -U <pkg>` + awk (стабильно), `dumpsys` — запасной
  (`userId=` на A11, `appId=` на A16). Первая версия разбора молча давала «uid=нет» на Android 16.

## Дублирование между разделами лога — снято (правка 2)

Пользователь: «логгировщик всё ещё дублирует вывод данных между разделами». Лог он удалил, искал по
скриптам. Найдено **три** класса повторов, все три устранены.

**Правило, которое теперь держится:** каждое данное попадает в лог **ровно один раз**.
- *состояние* (что сейчас на устройстве) принадлежит **снимку** `diag.sh`;
- *действия, rc и решения* (что сделали и по какой ветке) — **скриптам**; скрипт **не повторяет**
  значение, которое печатает снимок.

**(1) Строки скриптов против снимка.** `fs-type /storage/emulated/0` печатался за загрузку
**шесть** раз: `post-fs-data: fs-type`, `post-fs-data: итог`, `service: fs-type до`,
`service: посылка: … fs-type=`, `service: fs-type после` и снимок (и вдобавок дважды внутри снимка).
Так же дублировались `sdk`/`model`, `persist.sys.fuse`+`sdcardfs.enabled`, `vold-fusefs --check`,
метка state, режим `/data/media/0/Android`, «`/data/media/0` нет». Убрано:
- `post-fs-data.sh`: шапка → `=== boot: post-fs-data ===` (без sdk/model); удалены `старт:`,
  `fs-type:`, `state: … -> <ls -1dZ>`, `итог:`;
- `service.sh`: шапка без sdk; удалены `fs-type до:`, `fs-type после:`, **строка `посылка:`**;
  решения стали `vold-noacl: пропуск (патч не встал)` / `(fs=fuse)` — ветка без повторения числа;
- `storage.sh`: удалены `storage.sh: /data/media = <метка>` и `… /data/media/0/Android = <режим>`;
  «нет каталога» → `storage.sh: /data/media/0 пропущен (нет каталога)`;
- **метки SELinux переехали в снимок**: `--- модуль ---` теперь печатает
  `метка /data/media:` и `метка state:` — метка это состояние, а не действие.

**(2) Два раздела про один объект.** `--- форма хранилища ---` и `--- mounts (emulated) ---`
описывали одно и то же; форма `/storage/emulated/0` шла и магией, и строкой монтирования.
Сведены в один `--- хранилище ---`, и внутри владелец у каждой стороны свой: сырое дерево
(`/data/media`, `/data/media/0`, `/data/media/obb`) — магией ФС; то, что обслуживает `/storage` —
**таблицей монтирований**, и только ею. Магия `/storage/*` печатается **только если строки
монтирования нет** — это и есть случай tmpfs (`1021994 (монтирования нет)`), который иначе потерялся
бы.

**(3) `--path` и `--probe` дампили один каталог дважды.** Введены `dump_once` / `probe_once`
(список уже напечатанного **внутри одного снимка**). Ключ — **буквальный** путь: `/storage/emulated/0/X`
и `/data/media/0/X` **не** сводятся друг к другу, потому что при живом FUSE это разные объекты
(вид приложения и сырое дерево) — свести их значило бы стереть ровно то различие, ради которого
снимок снимается.

Проверено: `sh -n` на всех пяти скриптах; `dump_once` и fallback-магия — стендом на хосте
(повтор пути не печатается ни для существующего пути, ни для «нет»); zip пересобран, 220474 Б,
md5 всех пяти скриптов внутри zip совпадают с рабочим деревом. Дока обновлена
(`docs/diagnostics.md`: правило «одно данное — один раз», таблица разделов, «как читать»).
**Телефон недоступен** (10.128.124.246 не отвечает) — установку и прогон на устройстве не делал.
